= Graph geometry, ready for your renderer

roc-graph-layout computes deterministic node positions, edge routes, and drawing
bounds. Your application supplies the graph and the actual sizes of its nodes;
the package does not choose fonts, measure labels, or render the result.

https://lukewilliamboswell.github.io/roc-graph-layout/assets/build-pipeline.svg[See a build pipeline arranged into directed
stages by Layered layout.]

https://lukewilliamboswell.github.io/roc-graph-layout/docs/[Read the API reference] for every layout family, its settings, and
the geometry it returns.

== Start with the structure you know

* A directed pipeline or dependency graph: start with *Layered*.
* An existing hierarchy: use *Tree*.
* A general network: explore *Graph* layouts.
* Domain-specific alignment and separation rules: use *Constrained*.
* Nested groups: use *Compound*.

Read xref:choosing-a-layout.adoc#choosing-a-layout[Choosing a layout] for the
differences, or browse the https://lukewilliamboswell.github.io/roc-graph-layout/docs/[versioned API reference] for complete
inputs and settings.

== Read the result

Positions are node centers and follow the input node order. Edge routes follow
the input edge order. A route can be a straight line, a polyline, or a chain of
cubic curves. Use the returned bounds to frame the drawing rather than assuming
all coordinates are positive.

For repeated solves of unchanged input and preparation settings, the prepared
APIs let you retain reusable work. Prepare again when the graph changes.

== Draw Mermaid text

The separate Mermaid package reads text, measures labels in Inter, computes
geometry and returns a picture or standalone SVG. The layout package remains
usable on its own with caller-supplied node sizes.

[cols="1,2",options="header"]
|===
|Declaration |Supported content
|`flowchart` or `graph` |Nodes, groups, labelled connections, cycles, directions and style classes.
|`sequenceDiagram` |Participants and actors, messages and replies, notes, activations and nested interaction blocks.
|`erDiagram` |Entities, attribute rows, keys and comments, identifying and non-identifying relationships, and cardinalities.
|`classDiagram` |Classes, attributes, methods, annotations, multiplicities and distinct relationship markers.
|`stateDiagram` or `stateDiagram-v2` |States, initial/final markers, transitions, composite states, choice/fork/join markers and notes.
|===

`Mermaid.svg(source)` selects the diagram family from its declaration.
`Mermaid.draw(source)` returns the same drawing as paths and text for a custom
vector renderer. Each family also exposes `parse` for inspecting its
source-ordered model. Unknown or unsupported syntax returns problems rather
than a partially interpreted drawing. The family API documentation lists
its supported syntax and limitations; this is not full Mermaid compatibility.

== Choose appearance without repeating defaults

Import `mermaid.Mermaid` and `mermaid.Theme`, then supply only the properties
you want to change:

[source,roc]
----
options = Mermaid.Options.{
    theme: Theme.Options.{ font_size: 16, max_label_width: 180 },
}
svg = Mermaid.svg_with(source, options)
----

The defaults use a white background, pale indigo nodes, muted connectors,
14-pixel Inter text, 1.4-em line spacing, and no shadows. Colours, outlines,
padding, corner radius and optional shadows are shared across diagram
families. Wrapping and font settings affect measurement before placement,
so the boxes receive room for their actual text. Flowchart group titles
wrap too. Flowchart and state style declarations override the theme where
supported. Arbitrary CSS and alternate font families are not interpreted.

Invalid numeric theme properties are reported together. Display SVG with
Inter available so visible text matches the measured advances. The package
provides `Mermaid.font_licence` for distributions that include the font data.
