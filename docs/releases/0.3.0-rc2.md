# roc-graph-layout 0.3.0-rc2

This release candidate expands Mermaid support and makes grouped directed
layout reusable outside Mermaid. It publishes two packages from the same
source, with the Mermaid package depending on this release's layout package:

- Layout package: `{package-url}`
- Mermaid package: `{mermaid-url}`

Declare only the packages your application uses. Drawing Mermaid text needs
the Mermaid package alone; it fetches the matching layout package and
roc-font dependency automatically.

## Mermaid diagrams

`Mermaid.svg` and `Mermaid.draw` now dispatch flowcharts, sequence diagrams,
entity relationship diagrams, class diagrams, and state diagrams. Each family
also exposes its parser and source-ordered model. Unsupported syntax and
invalid numeric theme options are reported explicitly; these families do not
yet implement the entire Mermaid grammar.

Defaults follow pinned Mermaid 12.2.0. Custom appearance remains opt-in through
`Mermaid.svg_with`, `Mermaid.draw_with`, and `Theme.Options`. Class and ER tables,
relationship end labels, sequence activations, state composites, and notes
receive space before layout. SVG labels should be displayed with Inter
available; missing-glyph rendering also depends on the viewer's fallback fonts.

The canonical comparison uses pinned Chrome on Linux x64. All 143 independent
cases pass their existing semantic, geometry, canvas, and image gates. Raw
flowchart image differences remain, including empty multiline rows and
documented text-preservation extensions; this is not a claim of universal
pixel parity. Five Mermaid-accepted flowchart fixtures remain explicitly
unsupported, and Mermaid's own renderer rejects two ellipse fixtures.

## Reusable grouped layout

The layout package adds `Layered.prepare_grouped` and `Layered.layout_grouped`
for directed graphs with recursive group ownership. Callers provide node
sizes, group padding and direction, node or group endpoints, and measured
edge-label dimensions. Results include source-aligned positions, group boxes,
routes, endpoint attachments, local layers, and edges routed against the flow.
Prepared layout remains total after successful validation.

The default core path needs no Mermaid syntax, renderer, font, or theme.
Mermaid supplies those policies separately. `Compound` continues to compose
groups that use different layout families. Flat and grouped directed layouts
share their geometric phases and numerical helpers.

## Compatibility

The breaking changes introduced in rc1 remain part of the proposed 0.3.0 API:

- `Layered.Settings.routing` is `[Straight, Orthogonal(Route.Settings)]`.
- Compound layered `edge_weights` and `min_spans` use whole-input edge indices.
- Cleaner orthogonal routing can produce routes different from 0.2.0.

The pure core extraction preserves all 391 saved native profiles byte for byte
on macOS and Linux. Subsequent Mermaid text-measurement changes intentionally
target Linux glyph bounds and resolve the six previous Linux oracle failures.

Automatic API comparison with 0.2.0 is unavailable: the current `roc bump`
cannot extract that release's public API because it references the unexposed
`Constrained.ConstrainedPrepared` type. This release uses the workflow's
explicit API-comparison exception, as rc1 did; no successful automatic
compatibility comparison is claimed.

## Verification and temporary exclusions

The canonical repository checks pass with the October 27 compiler, including
421 core tests, 510 Mermaid tests, all 17 runnable native examples, fuzz and
benchmark smoke tests, release-bundle examples, and reproducible documentation
archives. The independent Mermaid oracle also passes in Linux CI.

At the user's request, the node-editor service check, native smoke run, and
browser-test job are temporarily excluded. TODOs track
[Roc issue #12677](https://github.com/roc-lang/roc/issues/12677) and the remaining
Datastar inference errors, whose cause is not yet confirmed. These exclusions
do not disable package tests, runnable examples, or the Mermaid oracle.
`RUN_NODE_EDITOR_CHECKS=1` retries the service and smoke checks locally; the
repository variable of the same name enables all node-editor checks in CI.
