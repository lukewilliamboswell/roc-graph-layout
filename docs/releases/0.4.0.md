# roc-graph-layout 0.4.0

The layout and Mermaid packages support Roc
`nightly-2026-11-18-a520eed`. Maintained applications and authoring tools use
basic-cli 0.28.1; Mermaid uses the compatible roc-font 0.1.2 release.
Repository scripts independently pin `roc-stable` to the November 18 compiler.

- Layout package: `{package-url}`
- Mermaid package: `{mermaid-url}`

## Public type compatibility

Layered's ordinary and exact preparation paths now expose the same nominal
`Layered.Problem` type. Mermaid drawing/SVG operations and compound constraint
filtering use nominal `Try`. Callers with explicit structural result/problem
annotations should use `Try` and the associated public problem type instead.
The example applications use the real updated API and retain their recorded
outputs.

Version 0.4.0 crosses the pre-1.0 breaking-version boundary from 0.3.1. It covers
these nominal-type changes under the repository's existing version policy.
No successful automatic comparison with 0.3.1 is claimed: November 18 cannot
compile the old bundle, and November 7 cannot extract its unexposed
`Constrained.ConstrainedPrepared` capability type
([Roc #12506](https://github.com/roc-lang/roc/issues/12506)). The release gate
still validates the requested version, published baseline metadata and bundle
identities. No unrestricted API-comparison override is introduced.

## Temporary compiler and tooling workarounds

The layering fuzz target temporarily permits `13 * small + 8192` combined
allocation/reallocation calls for its 8-versus-32-copy comparison while
[Roc #13214](https://github.com/roc-lang/roc/issues/13214) is unresolved. The
original multiplier is 8. A 12x trial still caught another input, now retained
as a third named regression. This allowance tolerates the observed compiler
cost; it does not fix allocation growth or establish linear complexity.
Other fuzz limits, geometry/determinism/source-alignment assertions, leak
checks, fresh corpora, 200 inputs and seed 1 remain unchanged.

The optimized native Mermaid oracle uses `--specialize=no` for
[Roc #13207](https://github.com/roc-lang/roc/issues/13207). Preview/Site script
module tests use `--no-cache` for
[Roc #13215](https://github.com/roc-lang/roc/issues/13215). Cold runners pre-admit
the exact hash-verified Blueprint Core archive and fetch approved source archives
from their canonical anonymous URLs to avoid the source download
failure in [roc-automation #152](https://github.com/lukewilliamboswell/roc-automation/issues/152).
Compiler downloads temporarily use `verified-browser` for
[setup-roc #12](https://github.com/roc-lang/setup-roc/issues/12), preserving the
same immutable metadata, exact size/SHA-256, limits and credential isolation as
the failing asset API route. No source-integrity or credential check is disabled.

Each temporary implementation has an upstream-linked TODO and removal checks
in `CONTRIBUTING.md`. Regression inputs and native scale/model controls remain
when those workarounds are removed. No allocation baseline is accepted.

## Release validation

The candidate must pass the full Linux/macOS checks, native benchmark/fuzz
campaigns, canonical Linux Mermaid comparison/failure gates and documentation
build. Both exact archive consumers retain all 17 examples, including cold
checks, cold native builds and exact runtime output in application directories.

The existing node-editor service/browser exclusions remain unchanged and are
not included in the release's evidence. They remain tracked separately from
the 17 runnable archived examples.
