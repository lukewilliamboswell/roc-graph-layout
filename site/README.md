# Site build

Build the complete local site from the repository root:

```sh
python3 scripts/build_site.py
python3 scripts/serve.py
```

This requires the compilers pinned in `package/main.roc` and
`playground/app.roc`, Node.js for Wasm validation, and network access to the
immutable roc-signals `0.2.0-rc3` assets. `ROC` or `--roc` selects the package
compiler; `PLAYGROUND_ROC` or `--playground-roc` selects the Signals compiler.
The build rejects mismatched compilers, an unexpected Signals platform URL, a
runtime archive digest mismatch, and an existing output directory; use
`--output` to choose another destination. Nothing is published to GitHub.

The output contains static guides, the Signals playground under `playground/`,
and the generated API reference under `docs/dev/`. `--version` selects the API
version directory; `--base-path` sets its URL prefix (default
`/roc-graph-layout`). The build exposes the output directory only after every
build and Wasm validation succeeds.

For local serving at the domain root, build with `--base-path ''`. For a Pages
project-path check, install `playwright-core@1.63.0`, set `CHROMIUM` to a Chromium
executable, and run:

```sh
node scripts/test_site.mjs dist/site
```

`PLAYWRIGHT_MODULE` may point to the `index.mjs` of an existing playwright-core
installation. The browser test serves the actual output at its configured
project prefix and checks guides without JavaScript, all nine presets, input
edits, state restoration, reset, and API navigation.

`build-info.json` records the Signals release, immutable platform URL, and
verified runtime archive digest used by the build.

## Static guides only

The guides are generated by the released basic-ssg 0.11.0 platform pinned in
`main.roc`. They are ordinary HTML and do not need JavaScript or Wasm to read.
The interactive playground is a separate application linked from these pages.

From the repository root, using the compiler pinned in `package/main.roc`:

```sh
roc check site/main.roc
roc build site/main.roc --output=site-generator
./site-generator site/content site-output
cp site/public/site.css site-output/site.css
mkdir -p site-output/assets
cp examples/build_pipeline/output.svg site-output/assets/build-pipeline.svg
```

`site-output` contains the generated guide pages only; this command does not
build or copy the playground, API reference, or deployment assets.

Keep guide Markdown files directly under `content/`. Navigation and content
links are relative to that shared output directory so the pages work under a
GitHub Pages project prefix as well as at a domain root. Adding nested guides
requires making navigation relative to each page's output depth.

Only repository-authored Markdown enters the raw HTML slot in the page
template. Use the basic-ssg `Html` builders for additional template content.
